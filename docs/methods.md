# Methods

`PdSample` interprets one genome. Every call is made from that sample's BAM (`EnsureBam` converts a CRAM input first). Scores are additive points from `config/config.yaml`. They are a triage rank in the style of ACMG evidence categories, and they are not an ACMG/AMP classification. Scored LoF structural variants get `null_variant` points via `transcript_ablation` plus a configurable `sv_dosage_lof` bonus (default 8), because SVs do not carry ClinVar/CADD/REVEL/AVI in-silico fields used for SNVs.

For the Assess shortlist contract (filters → points → inheritance → rank → `candidates.tsv`), see [README § Variant prioritisation](../README.md#variant-prioritisation). Assess writes `report.html`, `qc_summary.json`, `candidates.tsv`, and `sample_summary.tsv` into the Terra `candidates` array. Sample-level APOE, m.2158T>C, haplogroup, PGS000902 PRS (all 90 SNPs), and mean MLC are the TSV only (not HTML or QC JSON).

## Callers

Small variants are single-sample HaplotypeCaller GVCFs, genotyped with GenotypeGVCFs and filtered with the GATK single-sample hard-filter expressions documented in the README. VQSR is a cohort fit, and no CNN model is bundled, so hard filters are the filter used here. The default interval list is the panel gene-span BED.

GATK-SV single-sample (v1.1.1, Scramble on / MELT off) runs by default. Optional workspace `sv_joint_vcf` supplies a cohort joint-called SV VCF: when `sample_id` is in the header the workflow subsets that sample and skips single-sample GATK-SV; when absent it falls back to `GATKSVPipelineSingleSample`. The reference panel and hg38 resource files are required inputs for the single-sample path, taken from the public 1KG bundle that tag defines (`gatk-sv-ref-panel-1kg-v1-0-1`) or from a matched panel in workspace data. Overlap uses the gene and exon BEDs under `resources/panel/`. SV INFO/AF (or CN_NONREF_FREQ) is stored as `cohort_af` for annotation only and is not used as a hard frequency filter — a rare gnomAD SV that is enriched in a small PD callset must still pass. When `sv.drop_depth_only_artifacts` is on (default), ingest keeps depth-only calls (`ALGORITHMS=depth`) whose FORMAT `EV` lacks PE/SR and whose `RD_GQ` or `OGQ` is at or below `depth_only_artifact_max_rd_gq` (default 5) as unscored `sv_artifact` rows, independent of cohort AF. They do not become Mendelian solves; they can still be pulled back as a second hit in a gene that already has `followup_reason`. That class includes recurrent FILTER=PASS IGV artifacts such as the SOX6 and OPA1 ~10 kb depth DELs that escape GATK-SV `DEPTH_LT_5KB`. `pesr_caller_qc` still drops raw Manta DEL/DUP that lack a depth genotype. Depth CN is FORMAT `CN`, else GATK-SV `RD_CN` (joint callsets often omit `CN`); ingest writes that value as `copy_number`. An exon-overlapping PRKN DEL just above 50 kb with `RD_CN` is not treated as a Manta artifact. `sv_panel_af` is reserved for a true GATK-SV reference-panel AF when available and is then filtered with the same ceiling as gnomAD AF. `pdvar` requires the SV VCF; it does not treat a missing file as a skipped call. A sample that is absent from an existing SV VCF header is still `SV not assessed` on that row of the coverage table.

ExpansionHunter uses the vendored 24-locus catalog (FGF14, NOTCH2NLC, BEAN1, LRP12, and FXN included). A repeat count is labelled `str_expanded` only when `str_loci.<locus>.pathogenic_min_repeats` and `citation` are both set and `max(REPCN) ≥` that floor. Cutoffs are STRchive v2.28.0 `pathogenic_min` values (https://strchive.org/; mirrored in `workflow/assets/expansionhunter_catalog_sources.tsv` with age-of-onset, typical onset, and pathogenic/intermediate ranges), except FMR1 which keeps the FXTAS/POI premutation floor (≥55) for PD triage while STRchive’s pathogenic range is the FXS full mutation. Motif purity, CAT/AGG interruptions, and combined CTA+CTG sizing for SCA8 are not modelled. AD/XL expansions set sample classification `solved`. AR expansions (RFC1, CSTB, FXN) set `solved` only when both alleles meet the floor and the pathogenic motif is confirmed (`AAGGG` for RFC1); until the motif is parsed, a one-allele RFC1 expansion is `partially_explained` with `followup_reason`.

Gauchian copy number 0, or an explicit deletion, becomes a homozygous `transcript_ablation` in `GBA1`. A named large recombinant (e.g. `RecNciI`) stays a structural variant unless the file itself marks it pathogenic. Short protein tokens in `GBAP1_like_variant_exon9_11` or `haplotypes.variants_allele*` (e.g. `L483P/`) are resolved through the GBA1-PD Browser to c./p. HGVS and emitted like catalog SNVs. Pathogenic SNVs in Gauchian's `other_variants` field use the same path; when the same c. HGVS is already present from VEP, the small-variant row is kept and Gauchian's `gba1_pd_class` is copied onto it. Gauchian and VEP GBA1 SNVs are joined to the shipped GBA1-PD Browser extract (`resources/gba1/gba1_pd_browser.tsv`; Parlar et al. Mov Disord 2023) by c. HGVS for PD severity class (`severe` / `mild` / `risk` / `unknown`) and a configurable score bump (`gba1_pd_severe` / `_mild` / `_risk`). Browser `severe` / `mild` / `risk` classes qualify as `risk_carrier` even when ClinVar is B/LB. Non-PASS HaplotypeCaller genotypes at browser coordinates are restored (`RescueSites`) before NormPass so alleles Gauchian never emits can still reach VEP. GBA1 and LRRK2 stay `partially_explained`.

MitochondriaPipeline 4.7.0.0 calls chrM. Optional **MitImpact 4** (`mtdna_mitimpact`, e.g. `MitImpact4_V059.csv`) annotates those alleles offline by POS/REF/ALT with ClinVar CLNSIG, MITOMAP disease status and clinical info, gnomAD v3.1 mtDNA AF_hom/AF_het, APOGEE2, MitoTIP, and MLC (plus gene/HGVS). **Haplogrep 3** (`quay.io/biocontainers/haplogrep3:3.2.2--hdfd78af_1`, tree `phylotree-rcrs@17.2`) classifies the same mt VCF (including a reused `this.mtdna_vcf`). Sample-level haplogroup, m.2158T>C genotype, and mean MLC excluding **that sample's** Haplogrep FoundPolys (haplogroup-defining variants present in the mt VCF) are written to `sample_summary.tsv`. There is no static haplotagging exclusion list in the repo. A row is kept only when FORMAT `AF` is at least `mtdna.min_heteroplasmy` (default 1%) and `MITOMAP_Disease_GenBank_Freq` is non-empty. Nuclear CADD/REVEL/AVI are not applied to mtDNA. Sample heteroplasmy is the curation gate and is not itself a score. Population rarity uses `max(AF_hom, AF_het)` so common heteroplasmic alleles are not treated as absent. Evidence points add MITOMAP confirmed P/LP (`mitomap_pathogenic`), APOGEE2 Pathogenic/Likely-pathogenic (`apogee_pathogenic`), MitoTIP Q1 (`mitotip_likely_pathogenic`), and MLC ≥ 0.5 (`mlc_high`), plus ClinVar and absent/rare gnomAD AF as for other alleles. High-evidence rows become `mtdna_pathogenic_candidate` (priority with AD/STR; must-keep on the shortlist; sample classification stays `partially_explained`, not `solved`). Other carried alleles stay `mtdna_variant` for QC and the full callset table but are not shortlisted, so score-0 / ClinVar B/LB haplogroup alleles do not fill the report. Neither status marks the sample solved. Unset MitImpact leaves `mtdna_annotation: not_assessed` and the raw mito VCF.

## Annotation and ranking

VEP 116 `--pick` supplies consequence, symbol, and HGVS. Academic **dbNSFP 5.4a** (VEP-ready `dbNSFP5.4a_grch38.gz` + `.tbi` via `dbnsfp` / `dbnsfp_index`) supplies missense/splice `CADD_phred`, `REVEL_score`, Eigen, MutationTaster, fathmm-XF, `clinvar_clnsig`, and fallback `gnomAD4.1_joint_AF` / `gnomAD4.1_joint_POPMAX_AF` (classic `FATHMM_*` is not in 5.4a). Complete nuclear AF for panel alleles (including intron/UTR/synonymous) comes from an optional panel-sliced **gnomAD v4.1 joint** sites VCF (`gnomad_af_vcf`), built from `gs://gcp-public-data--gnomad/release/4.1/vcf/joint/` with `workflow/scripts/build_panel_gnomad_af.sh`. `AnnotateGnomadAf` writes matching `INFO/gnomAD_AF` / `AF_popmax` from `AF_joint` / `AF_grpmax_joint`; `LiftGnomadInfo` fills any remaining empty AF from dbNSFP CSQ for Introme. Optional panel-sliced **ClinVar P/LP** (`clinvar_plp_vcf`; `workflow/scripts/build_panel_clinvar.sh` from `gs://gcp-public-data--gnomad/resources/grch38/clinvar/clinvar_20250504.vcf.gz`) writes `INFO/ClinVar_CLNSIG` on matching small-variant alleles and SV ids. There is no full-genome gnomAD VEP `--custom`. Optional genome-wide CADD/REVEL plugin inputs remain as a fallback. SIFT and PolyPhen come from dbNSFP (`SIFT_*` / `Polyphen2_HDIV_*`); cache-native VEP `--sift/--polyphen` is off by default (`vep_sift_polyphen`). Splice triage uses Introme (not a VEP SpliceAI column). `pdvar` maps `clinvar_clnsig` / `ClinVar_CLNSIG` to `clinvar_class`. Missing gnomAD AF is treated as rare. A real non-empty `this.vep_vcf` skips this VEP/gnomAD/ClinVar chain; empty or placeholder priors do not.

AlphaGenome Atlas AVI scores come from `workflow/scripts/annotate_avi.py`, a local Tabix lookup (`pysam==0.24.1`) of PASS SNVs in the normalized VCF against the precomputed AlphaGenome AVI SNV table (https://alphagenome.google/downloads). A row is used only when CHROM, POS, REF, and ALT all match, and the task fails if REF disagrees at more than 10% of looked-up positions. The table is GRCh38 and SNV-only. `avi_raw` and `avi_phred` are taken from the table. The table has no CDF column, so `avi_quantile` is `1 - 10^(-Phred/10)` from the published Phred. Phred is `-10 * log10(1 - CDF)` against all genome-wide SNVs: 20 is the top 1% and 30 is the top 0.1% (Cheng et al., medRxiv, 2026, doi:10.64898/2026.09.16.26363192; the model is Avsec et al., Nature 649:1206, 2026, doi:10.1038/s41586-025-10014-0). Those two bands add 1 and 3 triage points, the same scale as the moderate and high CADD bands, and a higher Phred breaks ties inside a tier. They are rank bands, not a pathogenicity cutoff. Indels and an unset `avi_table` leave `avi_phred` empty and add no points. Atlas outputs are for research modelling. They are not a diagnostic result and are not for training other models.

Introme v2 (`d6da48bc`) scores splice consequences on the panel BED (including SpliceAI). When panel gnomAD sites or dbNSFP annotated AF, `LiftGnomadInfo` exposes `INFO/gnomAD_AF` for Introme's rare filter. Introme scores are joined onto alleles already present in the sample callset. Uncalled Introme alleles are injected only inside genes that already have `followup_reason`: first at `introme_high` (0.9); if that gene has none, at `introme_second_hit_relaxed` (0.7, recorded as `introme_class` moderate so they do not take `introme_high` points). The global Introme evidence cutoff stays 0.9. A real non-empty `this.introme` skips Introme (`introme_status` `prior`). Empty, missing, placeholder, or zero-byte `this.introme` is treated as unset: `ProbePriorFile` takes a String path (no WDL `size()` / File localization) and Introme runs. The same probe gates every listed Terra intermediate (`this.vep_vcf`, `this.small_vcf`, `this.sv_vcf`, `this.expansionhunter_vcf`, `this.gauchian_json`, `this.mtdna_vcf`, `this.introme`, `this.avi_tsv`): a real non-empty file of the right kind skips only that producer; Assess still runs. A bad prior does not FileNotFound at `disk_gb`.

SNVs that sit in a Figure 3 donor window or a Figure 4 acceptor window are also labelled with the Sullivan et al. 2025 splice-disruption subgroup, %SAV, and n (Am J Hum Genet 2025;112:764-778). The call uses the picked transcript's GENCODE exon and the reference base. It does not add evidence points. Indels, and samples without the reference FASTA or GTF, stay blank (`splice_heuristics: not_assessed`).

Inheritance uses the panel CSV (`GBA` aliased to `GBA1`). Two qualifying heterozygous alleles in an AR gene are `AR_comphet_candidate`. A qualifying `AR_hom` (including an Introme intron hom) still labels other same-gene alleles; coding partners are not left `not_qualifying`. A LoF / exon-disrupting SV (DEL or intragenic DUP) plus a coding or ClinVar P/LP allele in the same AR gene are paired as `AR_comphet_candidate` even when the small variant was initially a single het; same-gene Introme-only intron "solves" (and intron `AR_hom` when a strong coding allele is present) are demoted to `AR_intronic_candidate` and ranked below coding/SV hits. Incomplete AR genes (`AR_single_het` or `review_conflict`) get a non-empty `followup_reason` on every allele in that sample×gene so Assess force-keeps them in `candidates.tsv` for second-hit review (sorted after Mendelian solves). Assess then searches those genes for low-depth nulls (GQ ≥ 20), ClinVar P/LP, depth-only exon SVs, and gene-scoped Introme hits (0.9, then 0.7 if none), and records which of those checks were empty. Intron-only / Introme `AD_candidate` rows are ranked at status priority 1, are not force-kept past the top-N shortlist, and set `partially_explained` rather than `solved`. MAPT `splice_gof` (exon-10 cassette) skips GoF intron demotion and is force-kept on the shortlist; intron-only MAPT is still `partially_explained`. Canonical `splice_donor_variant` / `splice_acceptor_variant` and ClinVar P/LP still solve. When `inheritance.qualify_clinvar_vus` is on (default), ClinVar VUS alleles also qualify for MOI hits below the usual tier floor (AD het or hom, AR single-het / comp-het / hom, and mixes with SV, P/LP, or Introme). Candidate ranking prefers ClinVar P/LP coding, then VUS coding, then non-coding VUS. AD genes carry a literature `mechanism` label (`gof` / `lof` / `dn` / `mixed` / `splice_gof`; sources in `resources/panel/ad_mechanism.SOURCES.md`). When `inheritance.demote_gof_ad_intronic` is on (default), weak intron / Introme-only hits in `gof` or `dn` AD genes become `AD_gof_intronic` (priority 6) because splice LoF does not create the toxic or dominant-negative protein; ClinVar P/LP and coding alleles stay `AD_candidate`. LoF and mixed AD genes keep the milder intron demotion. Unphased `AR_comphet_candidate` / `AR_hemizygous` pairs get a phase note on `followup_reason`. SNCA copy-gain is scored only for gene-scale multiplications (`PREDICTED_COPY_GAIN` or exon/TSS overlap and span ≥ 10 kb). When the sample is unexplained and the shortlist would be empty, a required module that is `not_assessed` (or an SV/Introme prior) writes a stub `candidates.tsv` row. Early-onset unexplained samples also force-keep recessive-eopd nulls that missed the tier floor. A biallelic finding in a risk gene such as GBA1 is `risk_biallelic` and counts as partially explained on the report. Off-panel alleles, including TTN truncations, are dropped by the panel filter.

Small-variant depth QC uses `min_depth` (default 10). Depth-only failures can still be kept when GQ and allele balance pass: HIGH-impact panel alleles within `depth_rescue_near_miss_factor` of the floor (default 2×, so depth ≥ 5), or any keep-consequence allele inside a same-sample LoF / exon-disrupting deletion down to `depth_rescue_lof_del_min_depth` (default 5). Rescued rows carry `depth_rescued` and `depth_rescue_reason` (`near_miss`, `lof_del`, or both).

## Phenotype concordance

`config/gene_phenotypes.yaml` includes profiles for `str_loci` expansion genes (SCA, FXTAS, C9orf72, RFC1, NIID, SCA27B, and related phenocopies) so cited STR expansions can receive `clinical_match` when onset or symptom keywords fit.

Optional sample column `phenotype_report` is a GP2-style text file copied into the Assess phenotype block when the patient has one. There are no separate sample-table columns for age at onset, symptoms, or ethnicity. The report layout is: `GP2ID`, sex, age at sample collection, PD status, levodopa, age at levodopa start, age at diagnosis, diagnosis type, age at onset, then exposures and comorbidities grouped as high or lower relevance. `NA` fields are dropped. `pdvar` compares parsed age at onset, symptom keywords, and ancestry with `config/gene_phenotypes.yaml`. Levodopa recorded as yes is a biomarker note on early-onset recessive genes. Comorbidity lines are printed on the report and are not gene-profile keywords. Onset inside the profile range, a symptom keyword that hits a key or atypical feature, and an enriched ancestry each count toward `phenotype_score`. `clinical_match` is `matched` when any of those agree, `unmatched` when onset is outside the range and nothing else agrees, `uninformative` when the gene has a profile but the fields neither confirm nor refute it, `no_profile` when the gene has no profile, and `not_assessed` when no phenotype file was supplied. The report lists risk candidates (`risk_carrier`, `risk_biallelic`, `moi` RISK, and `risk_allele_exception`) with that match. Concordance does not add evidence points. A higher `phenotype_score` breaks ties after tier and AlphaGenome Phred. Profiles cover every gene in the panel CSV, grouped as typical Mendelian PD, atypical parkinsonism, risk genes, low-evidence candidates, and differential diagnoses (dystonia, NBIA, PFBC, dementia/ALS, ataxia/HSP, mitochondrial, lysosomal/leukodystrophy, neurodevelopmental). A profile without `onset_range` is not scored on age. The profiles are a starter literature synthesis from GeneReviews, OMIM, and MDSGene (`config/gene_phenotypes.SOURCES.md`), not a systematic review, and need expert clinical review before use beyond triage.

Biomarker multipliers stay 1 while their citations are null. Sample classification (`solved` / `partially_explained` / `unexplained`) and explained-liability text appear in `report.html`. Numeric `explained_liability` is set only when `liability.penetrance` has a value and a citation; the shipped penetrance map is empty. Incomplete AR genes are tagged with `followup_reason` on `candidates.tsv` rows.

`panel_prs` is the cited **90-SNP PGS000902** score (Nalls et al. *Lancet Neurol* 2019; `resources/prs/pgs000902_nalls2019.tsv`), not the unused empty weights stub removed in PR 96. `CallSummaryLoci` (`bcftools mpileup` + `call` on `workflow/assets/summary_loci.grch38.bed`) genotypes all 90 SNPs plus APOE rs429358/rs7412 from the WGS BAM, including hom-ref, without adding APOE (or FGF14/NOTCH2NLC) to the Mendelian HaplotypeCaller panel. `score_in_panel_prs` is annotation (panel gene / 20 kb cis) and does not filter the sum. Missing PRS sites are not imputed as hom-ref.
