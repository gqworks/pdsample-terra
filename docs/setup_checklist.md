# Resources to stage

`PdSample` localizes these files. Example JSON paths are in `workflow/terra/PdSample.example.json`. Files that are not on public GCS, and the commands to copy them into a workspace bucket, are in [`workflow/terra/STAGING.md`](../workflow/terra/STAGING.md). `workflow/scripts/download_resources.sh` fetches the VerifyBamID files and the chr-prefixed somalier hg38 sites VCF (and the VEP cache when you pass `--vep`).

## You must supply

- **GCP requester-pays project (two places).** `gs://gcp-public-data--broad-references` is **requester pays**. (1) **Cromwell localization** — when Terra copies inputs onto the VM, it must bill a GCP project. Set **`google_project`** in [workflow options](https://support.terra.bio/hc/en-us/articles/360026521831-Workflow-setup-VM-and-other-options) to your workspace **Google billing project** (Dashboard → Cloud Information). Example: `workflow/terra/PdSample.workflow_options.example.json`. That file also sets `read_from_cache` and `write_to_cache` so a relaunch reuses tasks that already succeeded. Turn on **Use reference disks** (`use_reference_disks: true`) so hg38 paths like `Homo_sapiens_assembly38.fasta` mount from a prebuilt disk instead of copying ~3 GB per task. (2) **Inside GATK tasks** — set method input `PdSample.requester_pays_project` to the same project (not the literal `YOUR_GCP_PROJECT`). That drives `--gcs-project-for-requester-pays` where the WDL passes it. `gsutil -u PROJECT` in a notebook uses the same idea.
- **GRCh38 FASTA, index, and dictionary.** `gs://gcp-public-data--broad-references/hg38/v0/Homo_sapiens_assembly38.fasta` plus `.fai` and `.dict`. The BAM or CRAM must match this reference (`EnsureBam` uses it when converting CRAM). The header check fails on an MD5 or `chr` prefix mismatch. When `ref_dict` is set (both Terra JSON files do), `CopyReferenceDict` localizes only the `.dict` for the first task, not the multi-gigabyte FASTA. Later tasks still read the FASTA from GCS (enable reference disks and `google_project` as above). If localization still fails, copy the reference trio once into your workspace bucket and point the method inputs at `gs://<workspace-bucket>/references/...` (no requester pays on your bucket).
- **VEP 116 cache, as a `.tar.gz`.** `https://ftp.ensembl.org/pub/release-116/variation/indexed_vep_cache/homo_sapiens_vep_116_GRCh38.tar.gz` (about 26 GB). The VEP task extracts it. There is no public GCS copy. Stage it with the commands in [`workflow/terra/STAGING.md`](../workflow/terra/STAGING.md). The example path is `gs://YOUR_WORKSPACE_BUCKET/resources/vep/homo_sapiens_vep_116_GRCh38.tar.gz`.
- **VerifyBamID2 2.0.3 SVD files (four inputs).** Vendored in `workflow/assets/verifybamid/` (defaults in `PdSample.wdl`). `download_resources.sh` can still refresh copies under `workflow/resources/verifybamid/`.
- **somalier sites VCF.** Chr-prefixed hg38 sites linked from the somalier v0.3.5 release notes: `https://github.com/brentp/somalier/files/3412456/sites.hg38.vcf.gz` (about 260 KB). The v0.3.5 release asset list is only the binary. Do not use `sites.hg38.nochr.vcf.gz`. Stage it with the commands in [`workflow/terra/STAGING.md`](../workflow/terra/STAGING.md). The example path is `gs://YOUR_WORKSPACE_BUCKET/resources/somalier/sites.hg38.vcf.gz`.
- **mtDNA bundle for MitochondriaPipeline 4.7.0.0.** Required inputs are `mt_fasta`, `mt_fasta_index`, `mt_dict`, `mt_amb`, `mt_ann`, `mt_bwt`, `mt_pac`, `mt_sa`, `blacklisted_sites`, `blacklisted_sites_index`, the shifted FASTA/index/dict/BWA indexes, `shift_back_chain`, `control_region_shifted_reference_interval_list`, and `non_control_region_interval_list`. Both JSON files point at the public hg38 chrM bundle under `gs://gcp-public-data--broad-references/hg38/v0/chrM/`, the same objects as GATK 4.7.0.0 `ExampleInputsMitochondriaPipeline.json`. Contig name is `chrM`. `blacklisted_sites` is `blacklist_sites.hg38.chrM.bed` with `blacklist_sites.hg38.chrM.bed.idx` beside it. That tag's `FilterMutectCalls` `--mask` takes this BED. The public prefix has no blacklist VCF. The same `requester_pays_project` used for the genome FASTA covers this bucket.
- **Introme hg38 GTF.** Stage GENCODE v44 to `gs://YOUR_WORKSPACE_BUCKET/resources/gencode/gencode.v44.annotation.gtf.gz` (Terra does not localize `https://` `File` inputs). See [`workflow/terra/STAGING.md`](../workflow/terra/STAGING.md). The Introme pin is `d6da48bc84abda66f588470f79abcf1244acfb21`.
- **`pdvar_git_commit` or a custom image.** The example uses `python:3.11.11-slim-bookworm` and `pdvar_git_commit` `main`, which installs `git+https://github.com/gqworks/pdsample-terra.git@main`. After the public snapshot exists, pin `pdvar_git_commit` to that commit SHA of `gqworks/pdsample-terra`. Or build `workflow/containers/pdvar/Dockerfile` and set `pdvar_docker`.
- **GATK-SV v1.1.1 reference panel and hg38 resources.** Structural-variant calling runs by default. `workflow/terra/PdSample.example.json` points at the public files tag v1.1.1 resolves from `inputs/values/ref_panel_1kg.json` (bucket `gatk-sv-ref-panel-1kg-v1-0-1`) and `inputs/values/resources_hg38.json`. `workflow/terra/PdSample.terra_inputs.json` binds the same inputs to workspace attributes. The full table is `workflow/terra/gatksv_panel_keys.md`. PdSample vendors a thin patched `GATKSVPipelineSingleSample` so Cromwell accepts v1.1.1 as a sub-workflow. To skip that pipeline, set sample columns `sv_joint_vcf` / optional `sv_joint_vcf_index` to a cohort joint-called SV VCF whose header includes `sample_id`; the workflow subsets that sample and does not call `GATKSVPipelineSingleSample`.

### One matched panel

Every panel file has to come from one bundle built with a GATK-SV version compatible with v1.1.1. Do not mix a cohort `ref_panel_vcf` or ped with the 1KG gCNV models or bincov matrix. The files that must move together are `ref_panel_vcf`, `ref_panel_ped_file`, `ref_panel_samples_list`, `ref_panel_bincov_matrix`, the PE/SR/SD file lists, `ref_panel_contig_ploidy_model_tar`, `ref_panel_gcnv_model_tars_list`, the std Manta, Scramble, and Wham VCF tars, the del and dup beds, `ref_panel_cutoffs`, the four genotype separation cutoffs, and the PE/SR metrics.

The public `ref_panel_1kg` JSON already combines more than one path family, and that combination is what the tag ships:

- `contig_ploidy_model_tar` is the 1KG **v2** gCNV tar under `gs://gatk-sv-resources-public/.../1KG/v2/gcnv/`. The gCNV model shards named by that bundle are the same public v2 tars. The list file, sample list, bincov matrix, del/dup beds, cutoffs, genotype separation cutoffs, and PE/SR metrics are under batch `38c65ca4-2a07-4805-86b6-214696075fef`.
- std Manta and Wham tars are GatherBatchEvidence `b705e9f6-c401-4a9a-a059-1a68d1ca5f98`.
- PE/SR/SD file lists are `gatk-sv-ref-panel-1kg-v1-0-1/lists/ref_panel_1kg.*.list`.
- The cleaned VCF is `mw-vcf-reshard/ref_panel_1kg.cleaned.vcf.gz`. The ped is public v1 `1kg_ref_panel_v1.ped`.
- `ref_panel_1kg.json` also has a batch `qc_definitions` TSV. The single-sample input is not that file. The Terra template sets `workspace.ref_panel_qc_definitions` from `resources_hg38.single_sample_qc_definitions` (`.../1KG/v2/single_sample.qc_definitions.tsv`).

Keep that set intact. Replacing only the ploidy tar, or only the VCF, breaks the match.

### Your own Terra panel

If the workspace was created from the GATK-SV featured workspace, the attributes are already there. Import `workflow/terra/PdSample.terra_inputs.json`, or set each input in the Terra Inputs tab to the expression in `gatksv_panel_keys.md`. Sample columns stay `this.sample_id`, `this.bam_or_cram_file`, `this.bai`, `this.sex`, `this.age_onset`, `this.symptoms`, `this.ethnicity`, `this.phenotype_report`, and optional `this.sv_joint_vcf` / `this.sv_joint_vcf_index`.

Panel attributes use the `ref_panel_*` names (`workspace.ref_panel_vcf`, `workspace.ref_panel_ped_file`, `workspace.ref_panel_samples_list`, `workspace.ref_panel_std_scramble_vcf_tar`, and the rest of that family). hg38 resource files use the `reference_*` twins (`workspace.reference_fasta`, `workspace.reference_genome_file`, and so on) plus clustering / GQ keys (`workspace.clustering_config_part1`, `workspace.recalibrate_gq_model_file`, …). `pesr_exclude_intervals` reads `workspace.reference_pesr_exclude_list`. `qc_definitions` reads `workspace.ref_panel_qc_definitions`. `empty_file` is not used at v1.1.1.

Docker inputs are not workspace attributes in this method config. Featured-workspace docker values can mix tags. Leave `sv_*_docker` unset so `PdSample.wdl` keeps the v1.1.1 pins.

## Optional

- **AlphaGenome AVI table.** Download "AVI SNV scores" (Tabix, about 88.5 GB, GRCh38) from https://alphagenome.google/downloads with its Tabix index. If no `.tbi` comes with it, build one with `tabix -s 1 -b 2 -e 2 alphagenome_variant_impact_score_snvs.tsv.gz`. Upload both to the workspace bucket. Set `avi_table` and `avi_table_index` to those paths. No API key is needed, so this works where the Atlas API is blocked (for example AnVIL). The task installs `pysam==0.24.1` and does a local Tabix lookup of PASS SNVs. Cromwell localizes the whole table for each sample, so the task disk is sized from the table. Check the header of the download is `CHROM POS REF ALT raw_score PHRED` (other common names are accepted). The example JSON leaves `avi_table` unset, which writes a header-only table and records `avi: not_assessed`. Scores are research ranks (Cheng et al., medRxiv, 2026, doi:10.64898/2026.09.16.26363192), not a diagnostic result.
- **Academic dbNSFP 5.4a** VEP-ready single file (`dbnsfp` / `dbnsfp_index`: `dbNSFP5.4a_grch38.gz` + `.tbi`). Supplies CADD/REVEL/in-silico scores plus `clinvar_clnsig` and `gnomAD4.1_joint_AF` / `POPMAX_AF` (no separate ClinVar or gnomAD VCF inputs). `LiftGnomadInfo` copies AF into INFO for Introme. Staging notes in `workflow/terra/STAGING.md`.
- **Optional genome-wide CADD / REVEL** (`cadd_snv`, optional `cadd_indels`, `revel`, and indexes) only if you need scores outside dbNSFP’s missense/splice scope. Splice triage uses Introme (not a VEP SpliceAI column).
- **Introme assets tar.** Optional `introme_assets_tar`: a workspace copy of `https://github.com/CCICB/introme/archive/d6da48bc84abda66f588470f79abcf1244acfb21.tar.gz`. Unset, the fetch task downloads that pin.
- **Introme image mirrors.** Defaults are the Docker Hub tags in `workflow/wdl/Introme.wdl`. Mirror them to Artifact Registry and override the `*_docker` inputs if Docker Hub pulls are blocked. SpliceAI, Pangolin, and MMSplice have CPU and GPU tags. `introme_use_gpu` selects the GPU tags.
- **Gauchian image.** `workflow/containers/gauchian/Dockerfile` installs `gauchian==1.0.2`. The default task pip-installs that pin into `python:3.11.11-slim-bookworm`.
- **Expression, SpliceVault, PRS weights.** File inputs on Assess. Expression and PRS numbers in config stay null until cited, so supplying a table does not by itself change the score.
- **`age_onset`, `symptoms`, `ethnicity`, and `phenotype_report`.** Optional sample-table columns. `phenotype_report` is a `gs://` text file in the GP2-style sheet layout. When a patient has it, Terra passes it into Assess. Age at onset, symptom keywords, and ancestry set `clinical_match`. Levodopa and the comorbidity list are recorded with the report. Blank cells skip concordance. Leave `phenotype_report` empty when there is no file.
- **Joint-called SV VCF.** Optional sample columns `sv_joint_vcf` and `sv_joint_vcf_index` (Terra binds `this.sv_joint_vcf` / `this.sv_joint_vcf_index`). When set, skips `GATKSVPipelineSingleSample` and subsets the VCF to `sample_id`. Leave both blank to run GATK-SV as usual.
